# PERF subsystem audit (2026-07-04)

## Architecture
RENDER LOOP (client): Game.frame() [Game.ts:5957-6012] is the single rAF loop: ocean.setWaveTime(perfNow/1000+serverTimeOffset) when offset!=null (5967-5969) -> ocean.update -> updateScene(dt) (6255-6331: lantern budget 6264, shipRenderer.update w/ snapshotAge clamped 0.22s at 6265, updateEnvironmentLod 6277, updateStormWeather 6282, updateWaterEnvironment 6308, throttled HUD/minimap/wisp timers 6311-6330) -> input send at 45Hz w/ signature dedupe + 0.2s heartbeat (5975-6003, consts Game.ts:29-30) -> renderer.updatePerformance (6006) -> renderer.render (6007) -> updateDebugPerfPanel (6009).

RENDERER (src/client/rendering/Renderer.ts): quality auto-detected once in detectRenderQuality() (652-666; '?quality=' URL override 653-654; cores<=4 or deviceMemory<=4 => low; 'high' requires >=8 cores AND pixels<=2.8M AND dpr<=1.5). init() (250-380): WebGLRenderer antialias:false (263-266), ACESFilmic exposure 1.12 (271-272), sRGB output, PCFSoftShadowMap 2048(high)/1024(balanced)/disabled(low) (269-270, 333-335), camera-following texel-snapped 170m ortho shadow box (updateShadowFrustum 524-545, consts 174-177), FogExp2 (253) driven per-frame by updateWaterEnvironment (448-488: fog/sun/ambient/hemi/exposure blended by day-night cycle 562-595 + storm + underwater depth). Pixel ratio: min/max per quality (226-229: low max 0.62!, balanced 1.5, high min(dpr,2)); adaptive scaler updatePerformance (394-424) drops -0.08 when avgFps<47, recovers +0.04 only after 8s cumulative >58fps. PostFx (PostFx.ts:63-90) built for balanced/high only: RenderPass -> UnrealBloom -> OutputPass -> FXAA (only when no MSAA; MSAA x4 only high+WebGL2) -> grade ShaderPass (high only); each pass calls WebGLRenderer.render(), and three r160 resets renderer.info at the start of every render() when info.autoReset (node_modules/three/build/three.module.js:29600); final ShaderPass draws Pass.js FullscreenTriangleGeometry = exactly 1 draw / 1 triangle.

DEBUG OVERLAY: enabled by ?debug/?perf (Game.ts:1622-1625), panel built at 6014-6040, refreshed every 0.5s in updateDebugPerfPanel (6042-6112). Reads this.renderer.renderer.info AFTER composer.render() (6058, printed 6106) => shows only the last post pass. 'snapshot Nms' (6069, 6110) = performance.now() - lastSnapshotAt, where lastSnapshotAt is set ONLY in applySnapshot (Game.ts:2737), i.e. it is snapshot AGE at panel-refresh time, not send interval.

NETWORK/SNAPSHOTS: server Match ticks via setInterval(16ms) + wall-clock accumulator, max 5 catch-up steps (Match.ts:198-227; SERVER_TICK_MS=16 => 62.5Hz, constants/index.ts:356). tick() (733-853) early-returns when phase!=='playing' (739) — this also stops all snapshot broadcasts after match end. Every 2nd tick (SNAPSHOT_RATE=2 => 31.25Hz) buildSnapshot(includeStaticWorld = every 12th tick => 5.2Hz) is broadcast (847-852). buildSnapshot (3671-3679) = shallow spread of ENTIRE state (players, ships, sharks, wildlife, seaRocks, tradeSessions...) with islands stripped except on full ticks. No delta compression, no float rounding, plain JSON (broadcast 3810-3819 stringifies once). Measured at spawn: 82,962 B without islands / 210,491 B with (islands 127.5KB, seaRocks 37.4KB, wildlife 23.2KB) => ~3.3MB/s (~26Mbps) per client. Backpressure: snapshots are silently skipped per-client while ws.bufferedAmount > 512KB (3812-3815, const 122). Client: NetworkClient ws.onmessage -> handleMsg; 'state_snapshot' goes through queueSnapshot (NetworkClient.ts:121-131) which coalesces to the latest and defers delivery to the next requestAnimationFrame; 'join' fires onJoin synchronously inside ws.onmessage (86-92). Game.applySnapshot (2729-2757): preserves previous islands when snapshot.islands is empty (2730-2733), rebuilds id indexes, sets lastSnapshotAt (2737), EMA-blends serverTimeOffset 0.1/snapshot (2738-2743), and on island-bearing snapshots calls ensureWorldMeshes+syncChests+syncBarrels (2744-2748).

WORLD BUILD: ensureWorldMeshes (2776-2790) loops islands and synchronously calls buildIsland(island) for each missing one, plus buildSeaRockMesh per rock (2783-2788). buildIsland spans Game.ts:2872-~5855 (~3,000 lines per island, WORLD.ISLAND_COUNT=10): reef layers via createLayer (2960-3000), terrain cap grid sampled from shared getIslandSurfaceY via surfacePoint — 25x65 verts high / 19x49 balanced (3048-3049) — computeVertexNormals + slope/biome vertex colors (3074-3133), shore skirt (3137-3174), dock (3176-3350), tavern (3379-3506), caves (3510-3660), boulders/palms as InstancedMesh when GLBs loaded (3679-3706, 3768-3801) but per-mesh unique geometries for procedural palms/outcrops/driftwood/stalactites/tavern furniture/planks, then chests (5630-5681), barrels (5683-5709), upgrade stations (5711-5850), NPCs (buildStoryNpcMesh 5856-5955). AssetLibrary.clone shares geometry/materials across clones (AssetLibrary.ts:108-112). Disposal on round reset is handled (resetLocalRoundState -> disposeSceneObject, 1996-2070), so geom~4k is live count, not a leak.

LIGHT BUDGET: pooled warm lights exist — 4 lantern + 3 campfire PointLights shared scene-wide, nearest-N assignment at night (initLanternSystem 2093-2109, registerLanternEmitter 2113-2158, updateLanterns 2160-2199). But chest glows (5659-5661), upgrade stations (5789-5791), and story NPCs (5943-5945) each get their own always-visible PointLight gated only by the generous LOD radii in updateEnvironmentLod (6114-6181: lootRadius 340/520/760, upgradeRadius 420/620/820, npcRadius 360/560/760).

LOADING/JOIN FLOW: Game.init() (1743-1832) chunks boot work with yieldForLoadingPaint (double-rAF, 1916-1922). Menu 'match_start' -> onMatchStartFromMenu (1857) -> server 'join' message -> onJoin handler (2325-2340) synchronously applySnapshot (=> full 10-island build) then hides the loading screen on 200/650ms timers.

## Findings

### 1. [MAJOR] Debug overlay 'draw 1 | tris 1' reads renderer.info after the post chain's final fullscreen pass reset it
- Where: src/client/core/Game.ts:6058
- Why: updateDebugPerfPanel reads this.renderer.renderer.info at Game.ts:6058 (printed :6106) after Renderer.render() -> PostFx.composer.render() (Renderer.ts:503-504, PostFx.ts:106-108). In three r160, WebGLRenderer.render() calls this.info.reset() when info.autoReset===true at the start of every render (three.module.js:29600), and EffectComposer invokes render() once per pass. So the surviving counters describe only the LAST pass — FXAA/grade ShaderPass drawing Pass.js FullscreenTriangleGeometry (a single triangle: [-1,3, -1,-1, 3,-1]) — hence a constant 'draw 1 | tris 1'. Counters are only correct on quality=low (direct render, no composer). geom/tex come from info.memory which is never auto-reset, so those are real.
- Fix: In Renderer.init() (Renderer.ts:263-274) set this.renderer.info.autoReset = false, and at the top of Renderer.render() (Renderer.ts:494) call this.renderer.info.reset() before postFx.render()/renderer.render(). The panel read at Game.ts:6058 then sees the cumulative frame totals across all passes including the scene pass.

### 2. [CRITICAL] Join freezes the main thread: 10 islands x ~3,000-line buildIsland run synchronously inside the ws 'join' message handler
- Where: src/client/core/Game.ts:2776
- Why: NetworkClient fires onJoin synchronously from ws.onmessage (NetworkClient.ts:86-92); Game.onJoin -> applySnapshot (Game.ts:2330) -> ensureWorldMeshes (2744-2745, loop 2776-2790) -> buildIsland (2872-~5855) for all 10 islands plus buildSeaRockMesh per sea rock (2783-2788). Each buildIsland allocates hundreds of unique BufferGeometries/materials, samples getIslandSurfaceY per terrain vertex + skirt + every prop, deep-clones GLBs, and runs computeVertexNormals — a multi-second single task. This is exactly the Playwright 'waiting for scheduled navigations' hang: the click's microtask queue never drains. First render afterwards also compiles ~200 new shader programs in one frame.
- Fix: Make the join path async: keep the loading screen up (move the hide timers at Game.ts:2332-2339 behind the build), sort state.islands by distance to the local spawn, build one island per frame with the existing yieldForLoadingPaint() (1916-1922) or requestIdleCallback, then reveal. ensureWorldMeshes callers are already resilient: updateEnvironmentLod (6127-6129), syncChests/syncBarrels skip missing mesh records, so deferred islands render in when ready. Also hoist ocean.setIslands out of the per-island loop (see separate finding).

### 3. [CRITICAL] 'snapshot ~1000-1400ms' = real snapshot starvation: 83-210KB full-state JSON at 31.25Hz is silently dropped by the 512KB bufferedAmount gate (and the metric is also frame-quantized by rAF coalescing)
- Where: src/server/core/Match.ts:3815
- Why: The overlay value is snapshot AGE (performance.now()-lastSnapshotAt, Game.ts:6069/2737), i.e. how long ago the last snapshot was APPLIED. Two mechanisms inflate it to ~1s: (1) buildSnapshot (Match.ts:3671-3679) serializes the whole GameState with no deltas or float rounding — measured 82,962B without islands, 210,491B with islands (every 12th tick), ~3.3MB/s (~26Mbps) per client; broadcast() skips state_snapshot per-client whenever ws.bufferedAmount>512KB (Match.ts:3812-3815, const :122), so on any link slower than ~26Mbps the buffer stays saturated and clients receive snapshots at roughly the buffer-drain period (~0.5-1.5s) with no fallback keepalive. (2) NetworkClient.queueSnapshot (NetworkClient.ts:121-131) defers application to the next rAF, so when frames are long (world build/shader compiles) the age reads about one frame duration. Interpolation clamps age to 0.22s (Game.ts:6265, 6375-6378), so entities freeze 0.22s after each snapshot then teleport when the next arrives — gameplay effectively runs ~1s behind.
- Fix: Cut snapshot mass: stop resending immutable data — seaRocks (37.4KB) and wildlife-static fields ride EVERY snapshot; move seaRocks into the includeStaticWorld bucket (buildSnapshot Match.ts:3677 already does this for islands; the client already tolerates absent islands via Game.ts:2730-2733 — replicate that pattern for seaRocks, and drop islands from periodic snapshots entirely since they're immutable and sent in the join payload at Match.ts:501). Round floats before stringify (e.g. 2-decimal positions) — halves payload. Then the 512KB gate stops triggering; optionally add a minimal heartbeat snapshot (players+ships only) when the gate skips a client.

### 4. [MAJOR] Per-chest/per-station/per-NPC PointLights bypass the pooled light budget — up to ~20+ live point lights force shader recompiles and per-fragment cost on every lit material
- Where: src/client/core/Game.ts:5659
- Why: A pooled budget exists (4 lantern + 3 campfire lights, initLanternSystem Game.ts:2093-2109, nearest-N assignment updateLanterns 2160-2199), but buildIsland also creates an always-visible PointLight per treasure chest (5659-5661, visible=!lowDetail, on day and night), per upgrade station (5789-5791), and per story NPC (5943-5945). Their visibility is gated only by huge LOD radii (lootRadius 520m, upgradeRadius 620m, npcRadius 560m on balanced; 6121-6164), so standing near an island puts many point lights in the render list at once. In three.js forward rendering every visible light joins NUM_POINT_LIGHTS for ALL MeshStandardMaterials: each count change recompiles every lit program (hitching) and the per-fragment light loop scales with count x overdraw.
- Fix: Route chest/station/NPC warm lights through registerLanternEmitter (Game.ts:2113) so the existing nearest-N pool covers them with sprites beyond the budget, or gate light.visible by a short distance (<=25m) inside updateEnvironmentLod (6138-6165) instead of the loot/upgrade/npc radii.

### 5. [MAJOR] geom ~4k / high draw calls: buildIsland allocates a unique BufferGeometry + material per prop mesh in loops despite unit-geometry and InstancedMesh patterns existing in the same function
- Where: src/client/core/Game.ts:3265
- Why: Per-island loops construct new geometry per mesh: dock planks new BoxGeometry each (3265-3271), dock posts/rails (3281-3311), tavern furniture (3379-3502), cave stalactites new ConeGeometry each (3613-3624), rock outcrops new CylinderGeometry each (3737-3747), procedural palm trunks (3816-3818), driftwood logs (3932-3941). x10 islands (+ ~200 mesh sites in ShipRenderer x10 ships) => the observed ~4k live geometries, each its own draw call, and the shadow pass renders them all again (castShadow set widely, e.g. 3131). Ironically the file already demonstrates the fixes: shared unit geometries scaled per-mesh (palmFrondGeo/tuftGeo/bambooGeo etc. 2930-2937) and InstancedMesh for GLB boulders/palms (3701, 3794).
- Fix: (a) Replace loop-local geometry constructors with shared unit primitives + per-mesh scale (extend the 2930-2937 table with unitBox/unitCylinder/unitCone). (b) Merge each island's static same-material decor into one BufferGeometry per material via BufferGeometryUtils.mergeGeometries after build (docks, tavern, cave dressing are never animated). (c) Use InstancedMesh pools for repeated procedural props (stalactites, outcrops, driftwood) mirroring the boulder path at 3679-3706. Expect draw calls per island to drop from hundreds to <20.

### 6. [MAJOR] 'high' render quality is unreachable on any HiDPI display, so MSAA + grade pass and full detail never run on typical dev hardware
- Where: src/client/rendering/Renderer.ts:665
- Why: detectRenderQuality returns 'high' only when pixels<=2.8M AND dpr<=1.5 (Renderer.ts:665). Every Retina/4K display (dpr 2) fails the gate regardless of GPU, so the game runs 'balanced': FXAA instead of MSAA (PostFx.ts:70), 1024 shadow maps w/ normalBias 1.8 (Renderer.ts:334, 344), max pixel ratio 1.5 (227-229), effectScale 0.72 (386-388) which shrinks terrain grids to 19x49 (Game.ts:3048-3049) and cuts prop counts (scaledCount Game.ts:2890-2894). The only escape is the undocumented ?quality= URL param (653-654). This directly caps the perceived visual quality in the live screenshots.
- Fix: Make the dpr gate account for the pixel-ratio clamp that already exists: 'high' renders at maxPixelRatio min(dpr,2) with its own adaptive scaler, so gate on physical pixels at the CLAMPED ratio (innerWidth*innerHeight*min(dpr,1.5)^2) or on GPU heuristics (WEBGL_debug_renderer_info), and drop the dpr<=1.5 condition at Renderer.ts:665.

### 7. [MAJOR] Adaptive pixel-ratio scaler is a one-way ratchet on 60Hz displays: quick to drop, nearly impossible to recover
- Where: src/client/rendering/Renderer.ts:415
- Why: updatePerformance drops resolution -0.08 whenever avgFps<47 OR smoothed frame >1/42 (407-411), but recovery (+0.04) requires avgFps>58 AND smooth <1/55 sustained for >8s of accumulated windows (415-419) — on a 60Hz vsync'd display a game hovering 50-57fps satisfies neither branch, so recoverTimer decays (421-422) and the ratio parks near minPixelRatio (0.58 balanced, 0.44 low; :226) after any transient hitch (e.g. the join world-build). Combined with 'low' quality's hard max of 0.62 dpr (227-228), players end up permanently blurry after one bad moment.
- Fix: Loosen the recovery gate at Renderer.ts:415 to avgFps>55 (or frame-time headroom vs the display's refresh interval measured from rAF deltas), shorten the 8s dwell, and make recovery step symmetric (+0.08). Exempt the first ~5s after join (world-build hitch) from downscaling by resetting perfTimer/counters when a match starts.

### 8. [MINOR] updateStormWeather is a redundant dead path: everything it writes is overwritten by updateWaterEnvironment in the same frame
- Where: src/client/core/Game.ts:6282
- Why: updateScene calls renderer.updateStormWeather (Game.ts:6282) and then updateWaterEnvironment (6308 -> 7507 -> Renderer.ts:448-488) every frame. updateWaterEnvironment recomputes and reassigns the same fog color/density, sun/ambient/hemisphere/horizon intensities, sky storm uniform, sun-disc weather and toneMappingExposure that updateStormWeather (Renderer.ts:427-446) just set. Its 0.008 epsilon gate (429) means it usually early-returns, but when it does run its work is discarded ~1ms later; two writers for the same uniforms is a maintenance trap (edits to one silently do nothing).
- Fix: Delete the call at Game.ts:6282 and the updateStormWeather method (Renderer.ts:427-446); updateWaterEnvironment already receives stormWeatherIntensity via Game.ts:7507. Keep ocean.setStormIntensity (6283) which is independent.

### 9. [MINOR] ocean.setIslands rebuilt and re-uploaded once per island inside the world-build loop
- Where: src/client/core/Game.ts:2780
- Why: ensureWorldMeshes calls this.ocean.setIslands(state.islands.map(...)) INSIDE the per-island if-block (Game.ts:2777-2781), so joining a fresh world maps the full island array and rewrites the u_islands uniform 10 times back-to-back during the already-frozen join frame.
- Fix: Move the setIslands call after the for-loop in ensureWorldMeshes (Game.ts:2776-2790), executing once only when at least one island was built.

### 10. [MINOR] Snapshots stop entirely when phase !== 'playing', so end-screen clients' snapshot age grows unboundedly
- Where: src/server/core/Match.ts:739
- Why: tick() returns before the snapshot broadcast (Match.ts:739 vs 847-852) once state.phase becomes 'ended' (3641, 3662). Clients sitting on the death/win screen (until MATCH_GC ~ LobbyServer.ts:578-594) receive no state at all; the debug panel's 'snapshot Nms' climbs into the tens of seconds and any world motion (other ships sailing during spectate) freezes at the last pre-end snapshot — easy to misread as a network bug while debugging.
- Fix: Move the snapshot block above the phase early-return, or after setting phase='ended' keep broadcasting at a reduced cadence (e.g. every 30 ticks) so spectate/end screens stay live: hoist Match.ts:847-852 before line 739 guarded by tickCount % SNAPSHOT_RATE.

### 11. [MINOR] Dead/stale artifacts: unused Renderer.areShadowsEnabled(), false 'snapshot/delta' comment, wrong Hz comments
- Where: src/client/rendering/Renderer.ts:390
- Why: areShadowsEnabled (Renderer.ts:390-392) has zero callers in src/. Match.ts:847 comment says 'Send snapshot/delta' but no delta path exists — only full snapshots with islands stripped. Match.ts:121 comment claims '5 Hz at the default 60 Hz tick / 30 Hz snapshot cadence' and constants/index.ts:356 says '~60 Hz', but SERVER_TICK_MS=16 gives 62.5Hz tick / 31.25Hz snapshots / 5.2Hz full-world. These mislead anyone tuning network rates.
- Fix: Delete areShadowsEnabled (Renderer.ts:390-392); reword Match.ts:847 to 'Send full snapshot (world stripped except every FULL_WORLD_SNAPSHOT_TICKS)'; correct the Hz math in Match.ts:121 and constants/index.ts:356-357 or change SERVER_TICK_MS to 16.6667-derived scheduling.
