# TERRAIN subsystem audit (2026-07-04)

## Architecture
ISLAND TERRAIN PIPELINE (server-generated, shared heightfield, client-meshed)

1) GENERATION — src/server/world/MapGenerator.ts. generateIslands() (164-237) picks WORLD.ISLAND_COUNT=10 (shared/constants/index.ts:11) entries from a FIXED 14-entry roster (67-82: name/style/biome/seed/radius 40-112/coastBias/landmarks/forcedInlet), places them by rejection sampling in ±800 with gap max(145, r1+r2+46) (181-199); only position+rotation vary per match — everything else derives from the entry seed via mulberry32 (shared/utils/index.ts:12-20). buildProfile() (239-364) produces IslandProfile: footprintX/Z 1.08-2.0 (anisotropic ellipse), terrainStyle ∈ tropical|rocky|plateau|mountain|twin|archipelago, 3 gaussian-hill params (angle/offset/scale), peakBoost (mountains 1.05-2.05), ridgeAxis/ridgeBias, mesaBias, inlets[] (coves/bays: angle/width/depth, 310-337, roster forcedInlet 323-325), palette=BIOME_PALETTES[biome] (shared/props.ts:38-44). ARCHIPELAGO-CAPABLE: a single Island record with terrainStyle 'archipelago' drops seaLift below waterline between hills (utils 532-540, floor -3.5) so one heightfield renders as multiple islets with swimmable channels; 2 roster entries use it. Then a per-island mulberry32 stream generates caves (367-428), dock+flatten stamps (431-491), tavern (493-516), upgrade stations (518-547), camps (550-573), landmarks (581-659), chests/barrels/NPCs, and props (855-945: biome scatter tables 100-150, spacing via getPropSpacingRadius props.ts:56).

2) SHARED HEIGHTFIELD — getIslandSurfaceY (utils 447-621), the single terrain truth, fully deterministic (simplex noise seeded TERRAIN_NOISE_SEED 0x51a7e11, utils 22-23; no Math.random). Math: getIslandDistRatio (338-347) = elliptical normalized distance with per-angle bulge from getIslandShapeTerms (322-336; ridge cosine + hill masks, shrunk by getIslandInletCut 307-320 → coves pull the shore inward). Coast bands: getIslandCoastField/Weights (365-392) = seeded 3-harmonic sin field + coastBias → beach/rocky/cliff weights (inlets force beach). Height = seaLift plinth (base 5.15+r*0.0085 lerping at rim to beachLift 2.3+/rockyLift 3.9+/cliffLift 7.4-10, 522-529) + beachRise/cliffRise/plateauRise/crownRise (472-485) + 3 gaussian hills (hillContribution 459-471; mountain peaks reach ~r*0.5 via peakBoost*3.2, 493-501) + angleNoise (516-519) + interior-masked fbm hillDetail & ridged cliffBands (553-564, freq 0.016/0.021, finest feature ~14m) + soft terraces (572-584, step max(2.4, r*0.055)). Past the rim the SIGNED shore drop continues UNDERWATER: beach eases to +0.42 wet sand by distRatio 0.97 then to −2.6 by 1.15; rocky→−3.4 by 1.14; cliff plunges to −5.5 (588-598). Structure stamps flatten discs (600-609). Cave carve is OPT-IN via {carveCaves:true} (611-615; getCaveCarve 409-445) — currently no caller passes it; caves are consumed via getCaveFloorY (626-631) and getCaveCeilingY (635-653). isSubmergedAt (658-661) flips walk↔swim vs gerstnerHeight.

3) CONSUMERS of getIslandSurfaceY (every new terrain feature must serve all of these identically): PhysicsSystem.ts 529 (fall landing), 681-687→islandStandY 1294-1308 (walk floor, cave-aware: stand on getCaveFloorY when head below ceiling, LOCO.CAVE_HEAD_CLEARANCE=0.1 line 68), 1365-1370 (slope block), 1598-1614 (ship keel grounding depth + finite-difference normal); shared/raycast.ts 59-63 isInsideIslandTerrain (musket/cannon occlusion raymarch, used by Match.ts 2628, PhysicsSystem 957, BotSystem 467); MapGenerator 407 (cave roof check), 950-953 slopeAt; shared/props.ts 85/99 (prop collider base Y, resolvePropCollision 67-95 ← PhysicsSystem 674/1317-1344); Match.ts 1352, 1576, 2310, 3257, 3842, 4136; BotSystem 547; Game.ts terrain mesh (3058 via getIslandSurfacePoint utils 663-674), ~30 decor call sites (4055-5336), chest visuals 5626/10271, local prediction 6513.

4) CLIENT MESH — Game.ts. Snapshot handler builds each island once (2778-2779) via buildIsland (2872-5620) into a THREE.Group at island.position under this.environment, cached in islandMeshes (1700). Parts: (a) submerged reef cylinder createLayer (2939-3042); (b) terrain cap: polar grid, rings 0..radialSegments (14 low/18 balanced/24 high) × angular segments (36/48/64), distRatio=pow(ring/N,0.9) so max=1.0, positions = getIslandSurfacePoint(+0.02) (3048-3072); computeVertexNormals then per-vertex colors (3081-3125) from coast weights, heightNorm=clamp(pointY/(r*0.18)), slope, distRatio masks lerping sand→beach→cliff→mud→grass→jungle→rock→peak with ±0.035 noise; material MeshStandardMaterial{vertexColors:true, roughness .98, DoubleSide} (3127-3130) — vertexColors IS enabled; (c) shore skirt: 26-44 segment vertical curtain from distRatio 0.978 down to −max(3.4, r*0.14), colored cliff/mud (3137-3174); (d) dock (3176-3359, GLB modules or box fallback), tavern (3361-3508); (e) cave interiors: entrance boulders/walls/ceiling/torch per island.caves (3510-3667); (f) CLIENT-ONLY decor scattered by a sine-hash rng seeded from island.id char codes (2883-2887, uuid→different every match): instanced GLB boulders (3670-3734), outcrops (3736-3758), palms (3760-3900), bamboo, beach wreck (3982+), ruins (5448-5479), terraces (5481-5498); island.props from the server is NEVER read in src/client; (g) LOD proxy: hardcoded flat-shaded sand/grass/rock cylinders+cone (5558-5617), toggled in updateEnvironmentLod (6114-6136) by camera-to-CENTER distance vs detailRadius 180/300/420. Quality is fixed at startup (Renderer.ts 225, detectRenderQuality 652-665; getEffectScale 386: .48/.72/1). Lighting: sun 2.75 + ambient .68 + hemi .78, ACES tonemapping, FogExp2 0.0015 (Renderer.ts 253, 271-273, 331-358). Ocean: OceanRenderer.ts vertical-only Gerstner from shared WAVE_PARAMS (14-35), shore damping/shallow-tint/foam from shoreDist = circle SDF over u_islands (37-48, 162-208), fed once with r=island.radius (Game.ts 2780).

5) WHERE NEW FEATURES GO — coves/bays already exist as profile.inlets (add wider shapes in MapGenerator.buildProfile 310-337 + getIslandInletCut falloff 307-320); ridges = ridgeWave (456-458) + cliffBands (561-564); valleys = hillDetail fbm (556-559) or negative gaussians alongside hillContribution (459-471); cliffs = coast field bias (365-392) + cliffY drop (597). All must live in shared utils (deterministic; no Math.random; seeded from profile.seed) so all consumers in (3) agree. Caves: WALK-IN CAVES ALREADY WORK end-to-end — generation (MapGenerator 367-428: entrance ≥3.2m up, roof-thickness check getIslandSurfaceY ≥ ceilingY+2 along tunnel), shared floor/ceiling math (utils 409-653), server locomotion (PhysicsSystem 681-687/1294-1308), client interior meshes (Game.ts 3510-3667). The heightfield stays single-valued (no overhangs possible in it); the pattern for caves/overhangs is: natural surface = roof, parametric interior volume (floor/ceiling fns) swapped in when the player's head is below the ceiling. Extend by adding new shapes to getCaveCarve/getCaveCeilingY + matching client meshes; known parity gaps: raycast solidity (raycast.ts 62) and client prediction (Game.ts 6513) ignore cave interiors — see findings.

## Findings

### 1. [CRITICAL] LOD gate ignores island radius — most visible islands render as the flat-shaded monochrome proxy cylinders
- Where: src/client/core/Game.ts:6133
- Why: updateEnvironmentLod picks detail vs proxy by camera distance to the island CENTER (6129: distance2D to island.position) against detailRadius 180/300/420 (6119). Island shorelines sit at radius*footprint(1.08-2.0)*bulge from center — up to ~250m (getIslandMaxRadius, shared/utils:681-686). So at sea virtually every island beyond ~300m — i.e. almost everything on screen — shows proxyRoot: hardcoded flatShading cylinders+cone (5568-5596) with no biome palette, no silhouette match, binary pop. On 'low' quality (180m) the proxy can even show while standing ON a big island. This is the direct cause of the 'flat-shaded monochrome smooth domes' screenshots; the vertex-colored terrain exists but is almost never the thing being looked at.
- Fix: In updateEnvironmentLod compute const edgeDist = dist - getIslandMaxRadius(island) and use edgeDist < detailRadius (import getIslandMaxRadius already used elsewhere in Game.ts). Raise detailRadius (islands are the landmark visuals; 420/650/900 is closer to AAA). Replace the proxy cylinders with a low-res version of the real cap: reuse the ring loop at 3054-3072 with radialSegments=6/angularSegments=20 and the same vertex-color code (3083-3125) so distant islands keep silhouette+biome color; tint any remaining proxy mats from island.profile.palette instead of 0xd7bd7f/0x4f8433/0x635b49.

### 2. [CRITICAL] Server prop registry (island.props) is never rendered on the client — invisible colliders and walk-through visual trees
- Where: src/client/core/Game.ts:3670
- Why: MapGenerator.generateProps (MapGenerator.ts:855-945) writes the deterministic prop registry (palms, boulders, crates, campfires, lantern posts, watchtower/shipwreck/standing_stones landmarks, dock modules) and the server collides players against it every tick (PhysicsSystem.ts:674 → 1317-1344 → shared/props.ts resolvePropCollision 67-95). But `island.props` appears NOWHERE in src/client (only BIOME_PALETTES is imported from shared/props.js, Game.ts:7). Instead buildIsland scatters its OWN boulders/palms/wrecks from a client-local sine-hash rng (2883-2887, 3670-3800, 3982+). Result: players are shoved by invisible palms/towers, while every visible client palm/boulder is intangible; roster landmarks (watchtowers, standing stones, camps) never appear at all.
- Fix: In buildIsland, after the terrain cap, iterate island.props: bucket by prop.type, build one InstancedMesh per type via assets.mergedGeometry(type) (same pattern as 3677-3707), matrix = compose((prop.x-island.position.x, getPropGroundY(island,prop) (shared/props.ts:98), prop.z-island.position.z), yaw=prop.yaw, scale=prop.scale); fall back to buildPropInstance (2080) per prop when merged geometry is missing. Delete or demote the client-only scatter loops (3670-3980, 5448+) to non-blocking micro-decor (tufts/shells) so visuals == colliders.

### 3. [MAJOR] Terrain cap stops at distRatio 1.0 and is skirted by a vertical rock curtain — beaches meet water at a hard elevated seam
- Where: src/client/core/Game.ts:3055
- Why: The ring loop's max distRatio is pow(N/N,0.9)=1.0 (3054-3061), but the shared heightfield continues underwater to ~distRatio 1.15 (utils 588-598: beach slides +0.42→−2.6, rocky→−3.4, cliff→−5.5). At the mesh rim, beach y≈+0.35 and ROCKY coast y≈+3.0 (rockyY smoothstep(0.96,1.14,·) is only ~0.13 at 1.0) — i.e. the outermost rendered ring floats above the waterline. The gap is faked by the shore skirt (3137-3174): a near-vertical curtain hung from distRatio 0.978 straight down to −max(3.4, r*0.14), vertex-colored cliff/mud (3150-3153) even on beach coasts. So the visible waterline is a dark rock wall, the wet-sand walk-in slope the physics uses (isSubmergedAt utils 658) is never rendered, and swimmers near shore see terrain that doesn't match where they can stand.
- Fix: Extend the cap past the footprint: append ~4 extra rings sampling distRatio 1.0→1.16 with the same surfacePoint() call (heightfield already defined there), color them wetSand→turquoise-dark by depth in the color pass (reuse coast.beach weight), then either delete the skirt or keep it only below y=−3 as an underwater plinth closing to the reef layer (3027-3042). This makes the mesh follow the exact shared math and gives beaches a real waterline gradient.

### 4. [MAJOR] Ocean shore foam/shallows use a circular island model with r=island.radius — foam never appears at the real shoreline
- Where: src/client/rendering/OceanRenderer.ts:44
- Why: shoreDist() is `length(p - isl.xy) - isl.z` (39-47) and Game.ts:2780 passes r = island.radius. The true waterline sits at radius*footprintX/Z(1.08-2.0)*bulge with inlets (utils 322-347) — up to ~2x the circle. The foam band is only 2-17m wide (frag 202-207) and the turquoise shallow ramp 4-52m (163-166), so for any island with footprint >~1.1 the entire foam ring lies buried underneath the terrain mesh (circle is inside the footprint) — matching the observed 'no foam/blend at the seam'. Shore wave damping (vert 71) is likewise misplaced.
- Fix: Minimum fix: pass r = getIslandMaxRadius(island) (shared/utils:681) at Game.ts:2780 — foam then lands near/outside the true shoreline everywhere. Proper fix: widen the uniform to vec4(x, z, rx, rz) with rx=radius*footprintX, rz=radius*footprintZ and make shoreDist an elliptical SDF (length(p-c)/ellipseRadiusAtAngle - 1 scaled to meters); MAX_ISLANDS=16 ≥ ISLAND_COUNT=10 so payload fits. Inlet-accurate foam would need a small per-island distance texture baked from getIslandDistRatio.

### 5. [MAJOR] Vertex-color height masks saturate — biome palettes wash out to a uniform rock tint on mid/tall terrain
- Where: src/client/core/Game.ts:3093
- Why: heightNorm = clamp(pointY / (r*0.18)) never subtracts the sea plinth (seaLift ≈ 5.15+r*0.0085, utils 522-529, so even flat beach shelf starts at heightNorm ~0.4) and the denominator is far below real peaks (mountain hills reach ~r*0.5 via peakBoost*3.2, utils 493-501). Everything above y≈0.6*r*0.18 (~8m on r=74) blends 60% toward cliffColor via rockMask (3099, 3110) and 0.86+ adds peakMask — heightNorm clamps to 1 over most of the interior, so grass/jungle (3095-3098) get overwritten and every island trends toward the same gray-brown, with only ±0.035 per-channel noise (3117). Eight successive lerps (3104-3114) also average hues toward mud.
- Fix: Normalize by expected relief, not r*0.18: const seaBase = 5.15 + r*0.0085; const peakEst = r * (0.10 + profile.heightProfile*0.25 + (profile.peakBoost??0)*0.15); heightNorm = clamp((pointY - seaBase)/peakEst). Gate rockMask primarily on slope (slopeRockMask already exists, 3102) instead of absolute height, raise grass/jungle saturation contrast in BIOME_PALETTES (props.ts:38-44), and bump vnoise to ~0.08 with a low-frequency fbm hue shift so biome identity survives ACES tonemapping (Renderer.ts:271).

### 6. [MAJOR] Terrain mesh resolution cannot resolve the shared fbm/terrace/cliff-band detail — islands read as smooth domes even in detail LOD
- Where: src/client/core/Game.ts:3048
- Why: radialSegments is 14/18/24 and angularSegments 36/48/64 (3048-3049). A large island (r=112, footprint 2.0 → ~450m across) gets rings ~9-12m apart, while the heightfield's finest features are ~14m fbm octaves (utils 556-559, freq 0.016 lacunarity 2.1), ridged cliff bands at 0.021 (561-564), and terraces of 2.4-6m steps (572-584). Nyquist-undersampled, they alias away, leaving only the low-frequency plinth+hills — the smooth dome look. The polar fan also wastes density at the center (all rings share angular positions) and quality is frozen at startup (Renderer.ts:225), so islands built on a 'low' first frame stay 14x36 forever.
- Fix: Scale segments by island size: radialSegments = clamp(Math.round(getIslandMaxRadius(island)/4), 24, 56), angularSegments = clamp(Math.round(circumference/5), 64, 160) on high (a 56x160 cap is ~9k verts — trivial). Keep pow(0.9) ring bias but add a mid-ring densification around distRatio 0.85-1.0 where the shore drop needs resolution. This needs no shared-math change — getIslandSurfaceY already contains the detail; the mesh just never samples it.

### 7. [MAJOR] Projectile raycasts treat cave interiors as solid rock — players in caves can't shoot or be shot
- Where: src/shared/raycast.ts:62
- Why: isInsideIslandTerrain returns y <= getIslandSurfaceY(island,x,z) WITHOUT carveCaves, i.e. the natural hillside. A player standing on the cave floor (getCaveFloorY, 1-6m below the natural surface) is 'inside terrain': raymarchIslandSurface fires the ray-starts-buried early-hit (raycast.ts:111-114) for shots fired FROM a cave, and any shot INTO the mouth stops at the invisible natural surface. Consumers: Match.ts:2628 (musket occlusion), PhysicsSystem.ts:957, BotSystem.ts:467. Caves are otherwise fully walkable (PhysicsSystem islandStandY 1294-1308), so this is a gameplay-visible dead zone.
- Fix: In isInsideIslandTerrain, after the height test add a cave-air exemption: const ceil = getCaveCeilingY(island,x,z); if (ceil !== null) { const floor = getCaveFloorY(island,x,z); if (floor !== null && y >= floor - 0.05 && y <= ceil) return false; } (both helpers exported from shared/utils 626-653; deterministic, shared by client and server so hit registration stays in lockstep).

### 8. [MINOR] Client prediction snaps the local player to the natural hillside while the server has them on the cave floor
- Where: src/client/core/Game.ts:6513
- Why: Local-player ground resolution uses raw getIslandSurfaceY (6512-6513). Inside a tunnel the authoritative Y is the carved floor (PhysicsSystem.islandStandY 1294-1308), 2-6m below the natural surface, so clippedUnderTerrain (player.y < resolvedSurfaceY - 0.75, line 6528) fires with snap=1 (6534) and lerps visualY onto the hilltop above the cave — the rendered player pops out of the cave / jitters against server corrections while walking in.
- Fix: Mirror islandStandY: after computing the natural surface, const ceil = getCaveCeilingY(island, predictedX, predictedZ); if (ceil !== null && player.position.y < ceil - 0.1) { const cf = getCaveFloorY(island, predictedX, predictedZ); if (cf !== null && cf < natural) use cf + 0.03 instead; } — both helpers are already exported from shared/utils (626-653); Game.ts already imports from that module (line 6).

### 9. [MINOR] Proxy island meshes hardcode colors, ignoring the biome palette entirely
- Where: src/client/core/Game.ts:5568
- Why: proxySandMat/proxyGrassMat/proxyRockMat are fixed 0xd7bd7f/0x4f8433/0x635b49 (5568-5570), while the detail terrain keys off island.profile.palette (2902-2915). Because the proxy is what's shown beyond 180-420m (finding 1), volcanic, bone and lush islands are indistinguishable at sea — 'biome vertex colors not visibly working' even after the LOD gate is fixed.
- Fix: Build the three proxy materials from the palette already resolved at 2902-2908: sand=paletteSand, grass=paletteGrass.lerp(paletteFoliage,0.35), rock=paletteRock; or better, replace the proxy with a low-res vertex-colored cap per finding 1 and delete these mats.

### 10. [MINOR] Client decor rng is seeded from the per-match uuid island.id — 'fixed roster' islands look different every match
- Where: src/client/core/Game.ts:2883
- Why: islandSeed is a char-code hash of island.id (2883), which MapGenerator assigns via uuid() per match (MapGenerator.ts:205). All client-only decor (boulders 3684+, palms 3776+, wreck angle 3983, ruins 5450, terraces 5485, skirt jitter 3145, vertex color noise 3117) therefore reshuffles every match, contradicting the roster design contract 'silhouette, coast bands, caves, stamps and props are identical every match — players learn the islands' (MapGenerator.ts:47-49) which the server side honors via entry.seed (222).
- Fix: Seed the client hash from the replicated profile seed instead: const islandSeed = (island.profile.seed ?? 0) >>> 0 (profile.seed is set at MapGenerator.ts:359 and already serialized — getIslandCoastField consumes it client-side via utils 366). Decor then becomes stable per roster island; becomes moot for palms/boulders once finding 2 moves them to island.props.
